# herdr-app-mods

[Herdr](https://herdr.dev) の Mac アプリ向けの mod。1 フォルダが 1 mod。

| mod | 内容 |
|---|---|
| [right-sidebar](right-sidebar/) | 上のタブバーの `+` の右に置く、右サイドバーのパネルを切り替えるボタン（Issues/PRs / CI / .local）。押すとそのパネルを表に出して右サイドバーを開き、表に出ているパネルのボタンをもう一度押すと閉じる。右サイドバー宛ての命令（`herdr-app do right-sidebar.<命令>`）もこの mod が受け、行き先のパネルを表に出してから渡す（mod 宛ての命令は表に出ている mod にしか届かないため）。右サイドバーが閉じていれば開く。命令は `open-<番号>`（PR か issue かは自動で見分ける）/ `run-<run id>` / `chart-<名前>` / `chart-latest`（一番新しいグラフ。そのため `latest.json` は名前では開けない）/ `back`（表に出ているパネルの詳細から一覧へ戻る）/ `tab-issue` / `tab-pr` / `tab-ci` / `tab-local` / `tab-chart`。herdr-app-config の `my-layout` から使う。layout には id が `right-sidebar` の stack と、その子として id が `right-sidebar-github` / `right-sidebar-ci` / `right-sidebar-local` の block（同名の mod を載せる）が要る |
| [right-sidebar-github](right-sidebar-github/) | フォーカス中の terminal がいる repo の open issue と open PR（CI の集計・draft・レビュー状態）を Issues / PRs のタブで並べるパネル（初期表示は Issues）。一覧の上の検索バーに入れた語で repo 全体（closed / merged も含む）を `gh` で検索し、結果に一覧を置き換える。検索語は GitHub の検索クエリ（`is:closed` `label:` `author:` など）で書ける。初期表示は検索バーに Issues なら `is:open assignee:@me -has:parent-issue`、PRs なら `is:open author:@me` を入れた状態で、空にすると open なもの全件を出す。mine ボタンを押すと検索バーをこの条件に置き換えて検索し直す。行をクリックすると詳細（issue: ラベル・担当者・サブイシューの一覧（完了数 / 総数つき。行をクリックするとそのサブイシューを開き、back で親 issue へ戻る）・Markdown で描いた本文、PR: レビュー・checks・本文）を開く。検索欄に `#1234` のように番号だけを入れて Enter を押すと、その詳細を開く（PR か issue かは自動で見分ける）。`tab-issue` 命令は検索欄を全選択してフォーカスし、Enter で元の terminal へ戻す。一覧は自動では取り直さず、↻ ボタンを押したときだけ取り直す（初めて表示する repo だけは開いた時点で取得する）。`gh` CLI を実行する |
| [right-sidebar-ci](right-sidebar-ci/) | フォーカス中の terminal がいる repo の、現在ブランチの Actions run を並べるパネル。行をクリックすると詳細（job と失敗した step）を開く。取り直しは ↻ ボタンだけ。`gh` CLI を実行する |
| [right-sidebar-local](right-sidebar-local/) | フォーカス中の terminal がいる repo の `.local` 配下の Markdown（更新の新しい順に 20 件）と `.local/charts` 配下のグラフ定義（JSON）を Docs / Charts のタブで並べるパネル。Docs の検索バーは `.local` 配下の全 Markdown をパスで絞り込む（空白区切りの語をすべて含むもの）。行をクリックすると、Markdown で描いた本文かグラフを開く。Charts は `.local/charts/<名前>.json` に `{"type": "line" | "bar", "title": "…", "unit": "…", "labels": [...], "values": [...]}` を書くと、line は折れ線（last / max / min つき）、bar は横棒で描く（1 グラフ 1 系列）。定義が不正なら、どこが悪いかを詳細に出す。手元のマシンの `.local` は変更を監視して即時に一覧を更新し、別マシンの `.local` は ↻ ボタンと herdr のタブを移ったときに読み直す |
| [my-agents](my-agents/) | 同梱の `agents` mod（サイドバーの Agents 欄）を `mod.clone` で複製し、`spaces` mod の機能を取り込んで Spaces 欄と Agents 欄を 1 つのツリーにしたもの。space の行の下に、agent ごとの行（agent のアイコン＋pane 名）と、agent のいないタブの行（プログラムのアイコン＋タブ名）をタブ順に並べる。space の行はクリックで切り替え、ドラッグで並べ替え、右クリックでメニュー、シェブロンで折りたたむ。ブランチと ahead/behind の表示、worktree の space を親 repo の下に置く動きは `spaces` と同じ。ピン留めした agent は一番上の Pinned に移る。agent の行の下には、その agent が `hc run` で起動した子の行を並べる。子の行の名前は、terminal の名前・テンプレート名が無ければ、program が出した terminal の題名（project-threads の thread なら `<project>/<id> <題名>`）を使い、全文は hover で出す。`spaces` にあるマシン別の見出しと再接続は持たない。herdr-app-config の `my-layout` から使う。テストは `node --test my-agents/tests/label.test.mjs` |
| [permission-notify](permission-notify/) | agent が許可待ち（Herdr の「Needs you」）になったら macOS の通知を出す。対象は `my-agents` の一覧と同じ（pane を持つ agent は `agents()` の `blocked`、一覧の agent の子孫で pane を持たない terminal は `blocked` か `error`）。Needs you でなかった agent が Needs you になったときに 1 回だけ出す。mod が最初に見た状態と、途中で初めて見えた agent は覚えるだけにする（herdr-app の起動や読み直しで一斉に鳴らさない）。Herdr の window が前面でその terminal にフォーカスがあるときは出さない。通知は `terminal-notifier` で出し、音は付けない（herdr-app 本体の音と toast はそのまま）。押すと Herdr が前に出て、pane を持つ agent はその pane へ移り（`pane.focus`）、pane を持たない子は親の agent の pane へ移ってから重ねて開く（`terminal.peek`）。`terminal-notifier` や `herdr-app` が見つからなければ、herdr-app の画面内の通知で知らせる。画面には何も描かないので、layout に小さな block として置く（herdr-app-config の `my-layout` はタブ行の右端に幅 1px で置く）。`brew install terminal-notifier` が要る。テストは `node --test permission-notify/tests/notice.test.mjs` |
| [project-threads](project-threads/) | 1 つの依頼を複数の Claude Code に分けて進めるための一式（mod とスクリプトと prompt）。repo の `.local/hc-projects/<name>/` を 1 つの project とし、user と話す coordinator（対話の claude）が、作業を thread（herdr-core の別の terminal で動く claude）に任せる。Claude Code の mod には依存せず、起動と連絡は `hc` だけで行う。Claude Code の plugin は、`/pj-handoff` のためだけに command 1 つの小さなもの（`project-threads/plugin/`）を同梱し、`open` が `--plugin-dir` で coordinator に読ませる。mod は thread の一覧を pane に出す。thread の記録（`threads/<id>/thread.json`・`status.json`）と terminal の状態を合わせ、要対応（許可待ち・エラー・あなた待ち・行き詰まり）/ 作業中 / 対応完了（報告済み・停止）/ 待ち（待機中・未報告）のタブに分け、タブには thread の数を添える（開いたときは要対応を選ぶ）。選んだタブの thread を見出しごとに、id・題名・モデル・最新の報告の要約を並べる。行を押すとその thread の画面を重ねて開き（`terminal.peek`）、行の上のボタンでタブに出す・停止する。一覧は thread の起動と報告のたびに描き直す。使うときは herdr-app の terminal で、repo の中から `project-threads/bin/open <name>` を呼ぶ（`alias hc-pj=<この repo>/project-threads/bin/open` を勧める。`--new` で前回の会話を引き継がない）。project のフォルダを作り、右に一覧の pane を開き、その terminal で coordinator を起動する。coordinator は `bin/start`（thread の起動）と `bin/message`（追加の依頼。止まった thread は同じ会話を再開してから送る）と `bin/cleanup`（終わった thread の片付け。id を付けずに呼ぶと消せる / 残す thread の一覧を理由つきで出すだけで、一覧に載った id を付けて呼ぶと消す直前に判定し直して消す。消せるのは最後の報告が `done` で、その後に追加の依頼を受けておらず、作業中・許可待ち・エラーでなく、thread が `worktrees.txt` に記録した worktree がどれも未コミットの変更なしで、ブランチが default branch に取り込み済みか同じ先頭のコミットの PR がマージ済みの thread。消すのは記録した worktree とローカルブランチ、thread の terminal で、thread のフォルダは `threads/.deleted/` へ移す。リモートのブランチは消さず、片付けた id は使い直さない）を、thread は `bin/report`（`done` / `blocked` / `needs-you` / `waiting` の報告。coordinator の入力に届く。`waiting` には `--within <分>` で完了見込みを付ける）を呼ぶ。`open` は coordinator の terminal の子として見張り（`bin/watch`）を起動し、`waiting` の完了見込みを過ぎても次の報告が無い thread を coordinator に知らせる（coordinator と一緒に終わる）。別の project の coordinator へ依頼を送る（回送）ときは、coordinator が user の承認を得てから `bin/relay <自分の project のフォルダ> <送り先の project のフォルダ> --file <本文>` を呼ぶ。送り先の `project.json` の coordinator の terminal で、その project の coordinator の claude が動いているときだけ、先頭に `[project <送り元の名前> relay] 送り元: <フォルダ>` を付けて送る（シェルや terminal が無いときは送らずに失敗する。返事の経路は無い）。coordinator の会話が長くなったら、coordinator に「引き継いで」と言うか `/pj-handoff` を打つ（どちらも同じ手順）。coordinator が進行状況を `memory/progress.md` に書いて `bin/handoff` を呼ぶと、補助がそのターンの終わりを待って coordinator の terminal に `/clear` を打ち、続けて progress と thread の `status.json` を読むよう入力を送る。progress の保存より後に届いた報告は、`status.json` の時刻で拾う。`/clear` では prompt と許可の更新は効かないので、効かせるには開き直す。振る舞いは `prompts/coordinator.md` と `prompts/thread.md` で決まる。`.local/` は repo の `.gitignore` に入れておく。project の `CLAUDE.md` にほかのファイルを `@` で取り込むと、thread が起動時に許可の確認で止まる。テストは `project-threads/tests/run.sh`（`hc`・`claude`・`herdr-app`・`gh` を偽物に差し替える。`jq` と `node` と `git` が要る） |

## 入れ方

フォルダを `~/.config/herdr-app/mods/` にコピーし、`herdr-app check ~/.config/herdr-app/mods/<name>` で確認する。pane として開くなら `herdr-app do pane.split '{"direction":"right","mod":"<name>"}'`。

## 右サイドバーのパネルを足すとき

`right-sidebar-github` / `right-sidebar-ci` / `right-sidebar-local` は、同じ内容の `common.js`（repo ごとの取得結果と herdr のタブごとの表示の記憶、詳細の開閉、命令の受け取り）を 1 部ずつ持つ。Herdr は mod フォルダの外を import できないためで、直すときは 3 部とも同じ内容にする。

パネルを足すには、`common.js` を持つ mod フォルダを作り、`right-sidebar/main.js` の `PANELS` と `route` に行き先を足し、layout の `right-sidebar` の stack に子を足す。

## 注意点

- 右サイドバー宛ての命令（`right-sidebar.<命令>`）は、最後の 1 件だけが実行を待つ。ウィンドウが隠れているなどで描画が止まっている間に続けて送ると、先に送った命令は実行されず、最後の命令だけが実行される。続けて送るときは、前の命令が反映されたことを `herdr-app shot` で確かめてから次を送る
